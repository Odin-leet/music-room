# Music Room

Mobile, collaborative, real-time music app — live track voting, control delegation, and a shared playlist editor. See `docs/` for the full cahier des charges.

## Architecture

| Layer | Choice | Why |
|---|---|---|
| Mobile | React Native (Expo) | One codebase, one language, demoable on Android and iOS from day one. |
| Backend | NestJS (Node.js) | Structure that scales past one person: a module per service (`auth`, `track-vote`, `playlist-editor`) instead of one tangled `index.js`; built-in dependency injection makes services testable in isolation; guards give a single, auditable place to enforce ownership per request; `@nestjs/websockets` sits on Socket.IO for the real-time layer both services need. |
| Database | PostgreSQL | Relational integrity for users, events, licenses and votes; real transactions for the atomic vote-increment and fractional-position reordering logic. |

**Why not a backend-as-a-service (Firebase/Supabase)?** The brief says explicitly: *"the SDK you choose must not do your work."* A managed backend would hand-wave exactly the parts that are graded — auth, ownership rules, real-time sync, concurrency handling. NestJS + Postgres means every line of that logic is yours to explain at defense.

This is a monorepo using npm workspaces so `apps/api`, `apps/mobile`, and `packages/shared` can be installed and versioned together:

```
music-room/
├── Makefile
├── docker-compose.yml       # Postgres for local dev
├── .env.example
├── apps/
│   ├── api/                 # NestJS — generated by `make scaffold-api`
│   └── mobile/               # Expo — generated by `make scaffold-mobile`
├── packages/
│   └── shared/                # TypeScript types shared by api <-> mobile
└── docs/                      # cahier des charges, decisions
```

## Setup — run this on your own machine, in order

The npm registry isn't reachable from this cloud session's sandbox, so the scaffolding commands below need to run locally, where you have normal internet access.

```bash
git clone <your-repo-url> music-room && cd music-room

make env               # creates .env from .env.example — fill in real secrets after
make scaffold-api      # generates apps/api with the NestJS CLI (one-time)
make scaffold-mobile   # generates apps/mobile with Expo (one-time)
make install            # installs every workspace's dependencies
make db-up              # starts Postgres in Docker

make dev-api             # NestJS in watch mode, http://localhost:3000
make dev-mobile          # Expo dev server (scan the QR code with Expo Go)
# or: make dev            # both at once
```

`make help` lists every target.

## Planned module layout (next step: APIs + DB structure)

Not built yet — this is the shape the next pass will fill in, so the Makefile and folder layout already anticipate it:

**apps/api/src/**
```
auth/              # email+password, Google/Facebook, JWT access+refresh
users/              # profile + the 4 visibility tiers (public/friends/private/preferences)
track-vote/         # Event, Track, Vote — the V.2.1 service
playlist-editor/    # Playlist, PlaylistTrack — the V.2.3 service
common/             # ownership guards, DTO validation, exception filters
config/             # env validation (fails fast on a missing secret)
```

**packages/shared/src/** — `User`, `Event`, `Track`, `Vote`, `Playlist` interfaces, imported by both `apps/api` (as the DB/DTO shapes) and `apps/mobile` (as the client's expected response shapes), so the two apps can't silently drift apart.

## Links between the two apps

- `apps/mobile` never hardcodes the API host — it reads `EXPO_PUBLIC_API_URL` (see `.env.example`), matching V.5's "backend address must be configurable" requirement, and exposes it again as an editable field in the app's own settings screen once that's built.
- `packages/shared` is the compile-time link: a changed API shape becomes a red squiggly in the mobile app, not a bug found at runtime.
- Real-time (Socket.IO) event names and payloads get documented by hand in `docs/` once they exist — generated REST docs won't cover that half.
